# Banking Management System API Documentation

This document describes the HTTP API exposed by the Banking Management System backend.

## 1. Base URL

The API is served from the application root, typically on:

```text
http://localhost:8080
```

If a different port is configured in your environment, replace `8080` with that value.

## 2. Authentication

This project uses Spring Security with session-based authentication.

- Public endpoint: `POST /auth/login`
- After successful login, the server stores the security context in the HTTP session.
- Subsequent requests should include the session cookie automatically from the browser or your HTTP client.
- Logout endpoint: `POST /auth/logout`

### Login Request

```http
POST /auth/login
Content-Type: application/json
```

```json
{
  "username": "admin",
  "password": "admin123"
}
```

### Login Response

```json
{
  "message": "Login Successful"
}
```

### Logout Response

```json
{
  "message": "Logout Successful"
}
```

## 3. Roles and Permissions

The application defines these roles:

- `ADMIN`
- `MANAGER`
- `CLERK`
- `CASHIER`

Role checks are enforced using `@PreAuthorize(...)` on controller methods.

## 4. Common Response Formats

Successful responses usually return JSON objects or arrays. For validation or business-rule failures, the API returns an error response generated by the global exception handler.

Typical JSON success response:

```json
{
  "message": "Success"
}
```

Or resource objects like:

```json
{
  "id": 1,
  "name": "John Doe"
}
```

## 5. User Management

### User Endpoints

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `POST` | `/users` | `ADMIN` | Create a new system user |
| `GET` | `/users` | `ADMIN`, `MANAGER` | Get all users |
| `GET` | `/users/{userId}` | `ADMIN`, `MANAGER` | Get user by ID |
| `GET` | `/users/role/{role}` | `ADMIN`, `MANAGER` | Get users by role |
| `PATCH` | `/users/{userId}/password` | `ADMIN` | Change a user's password |
| `PATCH` | `/users/{userId}/status` | `ADMIN`, `MANAGER` | Change user status |
| `PATCH` | `/users/{userId}/role` | `ADMIN`, `MANAGER` | Change user role |

### Create User Request

```http
POST /users
Content-Type: application/json
```

```json
{
  "username": "clerk01",
  "password": "secret123",
  "role": "CLERK"
}
```

### User Role Values

```json
["ADMIN", "MANAGER", "CLERK", "CASHIER"]
```

## 7. Account Management

### Account Endpoints

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/accounts` | `ADMIN`, `MANAGER`, `CLERK`, `CASHIER` | Get all accounts |
| `POST` | `/accounts` | `ADMIN`, `MANAGER`, `CLERK` | Create account |

```http
POST /accounts
Content-Type: application/json
```

```json
{
  "customerId": 1,
  "type": "SAVINGS"
}
```

### Account Types

```json
["SAVINGS", "CURRENT"]
```

## 8. Transaction Management

### Transaction Endpoints

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `POST` | `/transactions/deposit` | `ADMIN`, `MANAGER`, `CASHIER` | Deposit money |
| `POST` | `/transactions/withdraw` | `ADMIN`, `MANAGER`, `CASHIER` | Withdraw money |
| `GET` | `/transactions/{transactionId}` | `ADMIN`, `MANAGER`, `CLERK`, `CASHIER` | Get transaction by ID |
| `GET` | `/transactions/account/{accountId}` | `ADMIN`, `MANAGER`, `CLERK`, `CASHIER` | Get transactions for account |

### Transaction Request

```http
POST /transactions/deposit
Content-Type: application/json
```

```json
{
  "accountId": 101,
  "type": "DEPOSIT",
  "amount": 2500.00
}
```

### Transaction Type Values

```json
["DEPOSIT", "WITHDRAW", "TRANSFER_DEBIT", "TRANSFER_CREDIT"]
```

## 9. Transfer Management

### Transfer Endpoints

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `POST` | `/transfers` | `ADMIN`, `MANAGER`, `CASHIER` | Transfer money between accounts |
| `GET` | `/transfers/{transferId}` | `ADMIN`, `MANAGER`, `CLERK`, `CASHIER` | Get transfer by ID |
| `GET` | `/transfers/account/{accountId}` | `ADMIN`, `MANAGER`, `CLERK`, `CASHIER` | Get transfer history for account |
| `POST` | `/transfers/reverse/{transferId}` | `ADMIN`, `MANAGER` | Reverse a transfer |

### Transfer Request

```http
POST /transfers
Content-Type: application/json
```

```json
{
  "fromAccountId": 101,
  "toAccountId": 102,
  "amount": 1000.00
}
```

## 11. Notes

- All write operations are protected by role-based access rules.
- The backend enforces validation for required fields and positive amounts.
- Use the same session cookie after login to access protected endpoints.
- The project currently uses the default Spring Boot app root and does not expose Swagger/OpenAPI docs by default.
